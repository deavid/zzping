# Phase 2 — Migrate components to the generic RoomActor<T>

Date: 2025-10-30

Objective
- Remove duplicated (de-)serialization from component NetworkActors.
- Adopt the generic zznet-room::RoomActor<T> per room/per peer, created by each component's RoomManager.
- Preserve architectural separation: MainActor continues to handle internal domain messages, not raw bytes.

Key design choices validated against current code
- Today, component NetworkActors both deserialize network messages and translate them into internal domain messages for the MainActor.
- A pure "delete the NetworkActor" approach would force MainActor to handle network types (e.g., PingerMessage), breaking separation. Instead, we keep a thin translator layer that maps network messages T to internal messages U without touching bytes.
- The new split:
  1) RoomActor<T> — centralized (de-)serialization only
  2) TranslatorActor<T> (per peer) — maps T → domain messages, and domain → T for outbound
  3) MainActor — unchanged, handles domain messages
- NetworkManager remains: owns per-peer translator lifecycle and wires RoomActor<T> to TranslatorActor<T>.

Success criteria
- All component crates (zzpinger, zzmem-db, zzcollector-state, zzintent-config) stop calling bincode::decode_from_slice in their code paths.
- For each component room, the inbound path is: PeerChannels → RoomActor<T> → TranslatorActor<T> → MainActor.
- The outbound path is: MainActor → NetworkManager → TranslatorActor<T> → RoomActor<T> (do_send(T)) → PeerChannels.
- All tests compile and pass; apps start and basic flows work.

Component-by-component migration plan (pilot first)

0) Common additions generated by Phase 1
- RoomManager::create_for_peer now receives outbound_to_peer (mpsc::Sender<(RoomId, Vec<u8>)>).
- RouterActor already passes this sender when creating rooms.

1) zzpinger (pilot)
- Files:
  - src/components/zzpinger/src/network_manager.rs
  - src/components/zzpinger/src/network_actor.rs (to be replaced by translator actor)
  - src/components/zzpinger/src/actor.rs (MainActor, unchanged handlers)
  - src/components/zzpinger/src/network_messages.rs (unchanged serialization definitions)

Steps:
- Replace PingerNetworkActor with PingerTranslatorActor (new file or repurpose the old path).
  - Remove Handler<InboundRoomPayload> and any bincode decode usage.
  - Implement Handler<PingerMessage> for inbound network messages (typed, already decoded by RoomActor<T>).
    - Map PingerMessage::UpdateTargets { targets } → MainActor.do_send(UpdateTargets { targets })
  - Implement public API for outbound sends, e.g., methods or Actix messages that the NetworkManager can use to instruct the translator to send a PingerMessage to RoomActor.
- In PingerNetworkManager::create_for_peer:
  - Use provided outbound_to_peer and the static room id RoomId::from("pinger").
  - Construct RoomActor<PingerMessage> with:
    - room_id: "pinger"
    - outbound_tx: outbound_to_peer.clone()
    - component_recipient: translator_addr.recipient::<PingerMessage>()
  - Start the RoomActor, keep its Addr in a per-peer map inside NetworkManager for outbound usage.
  - Return the RoomActor recipient::<InboundRoomPayload>() from create_for_peer.
- Outbound path:
  - NetworkManager decides when to send network messages (e.g., on domain events).
  - It finds the per-peer RoomActor address in its map and does: room_addr.do_send(PingerMessage::...)

2) zzmem-db
- Files:
  - src/components/zzmem-db/src/network_manager.rs
  - src/components/zzmem-db/src/network_actor.rs → becomes MemDBTranslatorActor
  - src/components/zzmem-db/src/network_messages.rs (unchanged)
- Transform like pinger:
  - MemDBTranslatorActor implements Handler<MemDBMessage> to translate to internal messages
  - NetworkManager creates RoomActor<MemDBMessage> and stores per-peer Addr
  - Remove all bincode::decode_from_slice from zzmem-db component

3) zzcollector-state
- Replace CStateNetworkActor with CStateTranslatorActor handling Handler<CStateMessage>
- Wire RoomActor<CStateMessage> from NetworkManager
- Remove bincode::decode_from_slice from component

4) zzintent-config
- Identify the network message T used for the "intent-config" room
- Mirror the translator pattern and RoomActor wiring

5) Wiring details and datastructures in NetworkManager
- Per component, add a field in NetworkManager:
  - per_peer: HashMap<PeerId, (Addr<TranslatorActor<T>>, Addr<RoomActor<T>>)> (or two maps)
- On PeerAdded/PeerRemoved:
  - Create/destroy the translator actor and keep its Addr
  - RoomActor<T> is created via create_for_peer (one per peer and room)
- Thread-safety: All access stays within actix context; per-peer maps are owned by the manager actor; no Arc<Mutex> required.

6) Backward-compatibility and incremental compile strategy
- Do zzpinger first; run cargo check and tests.
- Then zzmem-db; then zzcollector-state; then zzintent-config.
- After each component migration, run the workspace tests.

7) Tests to add/update
- Unit tests for translator actors (mapping T → domain and domain → T where applicable).
- Integration tests in zznet-router/tests to validate that after Router OnPeerConnected:
  - Sending a serialized frame lands on MainActor via RoomActor<T> + TranslatorActor<T>.
  - Outbound typed send via RoomActor<T> reaches HelloActor/TcpTransport (can be smoke-tested by capturing bytes).

8) Documentation updates (component-level)
- Update rustdoc headers in each component to explain the new split (RoomActor<T> for (de-)serialization, TranslatorActor<T> for mapping, MainActor for domain logic).

Deliverables for Phase 2
- For each component:
  - New TranslatorActor<T> (replacing old NetworkActor role, minus bytes work)
  - NetworkManager updated to:
    - Create and manage Translator per peer
    - Create RoomActor<T> in create_for_peer and return its InboundRoomPayload recipient
    - Maintain per-peer maps with RoomActor Addr for outbound
  - Removal of all direct bincode::decode_from_slice usage from component code

Acceptance
- Workspace compiles; all unit tests pass.
- Grep check: no bincode::decode_from_slice in src/components/** (allowed in tests or zznet-room only).
