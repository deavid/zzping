# `zznet-demo`: A Realistic Simulation for Framework Validation

This crate serves as a high-fidelity integration test suite and a living example of the `zznet` framework. Its primary purpose is **not** to achieve high test coverage numbers, but to simulate a realistic application with meaningful, end-to-end scenarios.

## Guiding Philosophy

Our testing philosophy is simple but strict: **realism over coverage**.

1.  **Emulate a Real Application**: The tests within this crate are designed to mirror the behavior of a genuine application built on `zznet`. We focus on "happy path" scenarios that represent the core functionality and intended use cases of the framework.

2.  **No Contrived Tests**: Writing tests solely for the sake of increasing code coverage is strictly prohibited. Tests must correspond to a plausible real-world interaction between components. If a line of code can only be reached by a contrived test, it's a sign of a problem in the code itself, not a lack of tests.

3.  **Coverage as a Diagnostic Tool**: The code coverage report generated by running this demo is a powerful diagnostic tool, not a goal in itself. Its value comes from what it *doesn't* show.

## How We Use Coverage

Any core framework code that remains **uncovered** after running the realistic simulations in this crate is immediately suspect. Uncovered code points to one of two possibilities:

*   **Dead Code**: The code is genuinely unused and should be removed.
*   **Design or Integration Flaw**: More critically, the code might be unreachable due to a flaw in the framework's design, component wiring, or overall architecture. It indicates that a part of the framework is not being used as intended, or cannot be used in a realistic scenario.

By focusing on building a high-quality, realistic simulation, we turn the coverage report into a tool for architectural validation and code health analysis. It helps us find and fix fundamental issues rather than just chasing a percentage.
